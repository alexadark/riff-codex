01What RIFF does

Know what happens next.

RIFF helps you turn an idea into working software. It keeps the plan, the checks, and the progress together while Codex coordinates the build.

/ 01

The brief

PROJECT.md says what you are building, who it serves, and where the edges are.

/ 02

Roadmap

ROADMAP.yaml turns the outcome into small useful steps in the order they need to happen.

/ 03

The checks

Checks and review look at the actual change before a step is marked complete.

/ 04

Dashboard

Progress files feed a local read-only dashboard. The dashboard observes; it cannot execute work.

“Describe the result you want. Follow the work. Try what gets built.”Your part in the process
02Start / install

Install once. Start building.

Run these commands in Terminal. Download RIFF once and keep its folder in place. Then connect your project by replacing the example path with your own. Your project must use Git; the installation guide covers new folders too.

git clone https://github.com/alexadark/riff-codex.git ~/riff-codex cd ~/riff-codex npm install npm link

cd /path/to/your-project riff-codex init

Before you begin

  • A GitHub account with access to RIFF Codex
  • Codex, installed and signed in
  • Git, for saving change history
  • Node 20 or newer, with npm
  • Bun, for the dashboard and setup check
Approve the automatic checks

Open a fresh Codex session in your project. Open /hooks, review and approve RIFF’s automatic checks. Then record your approval in Terminal with riff-codex doctor --record-hooks-approved. This command records your approval; it does not give it for you.

$riff:start

New project

Describe your idea in Codex. RIFF prepares the project brief and the first plan. It writes PROJECT.md and ROADMAP.yaml.

$riff:onboard

Existing app

Use this when an application already exists. RIFF reads what is there and plans improvements while preserving what works.

In the Codex conversationChoose RIFF start or onboard in the skill picker if the names are not visible. Details live in the installation guide. Run $riff:wave separately when you are ready to start building.

03Interactive flow

Request in. Proof out.

Follow the arrows from your request to a checked result. RIFF repeats the cycle while there is ready work. Select a step below to explore an example.

01 / BEGINUser request“Help me save recipes.”
02 / BRIEFPROJECT.mdWhat are we building?
03 / PLANROADMAP.yamlSmall useful steps
04 / READYSelect next ready stepEarlier steps finished
05 / BUILDCodex buildsOne useful step
06 / PROVEChecks + reviewContinue only if it passes
07 / SAVESave checked workKeep progress and history
08 / LOOPNext ready stepRepeat the work
06 fails → correct → recheck

If the correction passes, go to 07. If it still fails, record the blocker instead of marking the step complete.

Plan + progress ⇢ dashboard

The dashboard shows the plan, completed work, and blockers. You start work in Codex.

08 ↩ 04: choose the next ready step. When the plan is complete, the loop ends. The dashboard only displays information.

Step 01 / begin

Start with the outcome.

Say what someone should be able to do. RIFF uses that request to focus on one useful change at a time.

“Let me save a recipe and find it later.”

Step 02 / brief

Keep the goal clear.

PROJECT.md says who the app is for, what it should do, and what can wait.

PROJECT.md → what we are building

Step 03 / ready

Take the next useful step.

ROADMAP.yaml lists useful steps and what must happen first. RIFF chooses the most important step that is ready to begin.

Save a recipe → find it later → search recipes

Step 04 / proof

Build, check, review.

Codex builds the step, checks the changed behavior, and gets a fresh review. A saved recipe should be there when you look for it.

change → checks → review

Step 05 / loop

Keep progress and history.

RIFF saves the checked changes in your project’s history and records progress, then finds the next ready step. A failure gets a correction and a recheck, or a recorded blocker.

save → next ready step
04Daily use

Five moves you need.

Use the namespaced Codex skills from a project with RIFF enabled. Start or onboard shapes the work; wave runs it as a separate action.

$riff:status

See what is done, what is blocked, and what comes next.

$riff:status

$riff:wave

Start building or continue where you left off.

$riff:wave

$riff:quick

Make a small change that does not need a new plan.

$riff:quick

$riff:debug

Diagnose a concrete failure and make a focused correction.

$riff:debug

$riff:dashboard

Open the local read-only view of saved progress.

$riff:dashboard

Loop or guided

loop is the default: RIFF continues through ready steps. Choose guided during initialization when you want confirmation between steps. Revisit the preference with riff-codex init --configure.

# Run a RIFF wave

Read `.riff-codex/references/taste.md`, the project taste index and only the relevant topics/stack rules. For frontend work, apply `.riff-codex/references/taste/frontend.md`, use the required relevant design skills and obtain rendered browser evidence before visual acceptance. Persist proven reusable conventions before final validation and review; do not create a taste approval queue.

Read `.riff-codex/references/operating-contract.md`, `.riff-codex/references/execution.md` and `.riff-codex/references/model-routing.md`. They own autonomy, phase context, delegation, review, retry and stop rules. Use `PROJECT.md` as the dossier index and load only the selected phase's stories, criteria, data boundaries, rights, integrations and decisions. Load the security reference for a sensitive phase. A production application planned with the discovery manifest must pass `discovery check` before activation; finish all planning and design first. Existing projects without enrollment keep their established contract.

1. Read `.riff-codex/references/git-delivery.md` and establish or reconcile the evolution's scoped integration branch before implementation. Run `node .riff-codex/bin/riff.mjs wave sync`, then `wave resume` or `wave select [phase-id]`; activate the selected phase without bypassing dependencies. Follow `.riff-codex/references/learning.md` to reuse applicable lessons. On recovery, preserve working files and the index; inspect the resume result before doing work. A previously committed, fully verified phase may already have been completed by recovery.
2. Inspect `wave context [phase-id]`, then implement the complete demonstrable outcome. Reuse existing components/services and preserve agreed behavior. Delegate only substantial independent packages with settled contracts; concurrent writers use separate worktrees, while the primary agent owns integration and RIFF state. Keep phases sequential. Verify the assembled result, not just worker outputs.
3. Merge proven reusable lessons and perform observation triage for this phase before freezing the candidate. Read `.riff-codex/references/evidence.md`. Stage the complete candidate, then execute scoped validation with `wave validate --run` and explicit paths. For changed UI journeys, capture real screenshots and attach the verification manifest; link the generated HTML report in the result. A `smoke_test: true` phase requires recorded passing journey evidence. Reuse checks already observed for the same candidate and target. Use `wave retry` only for its recorded formal failure; do not repeat an unchanged failed attempt or reset its budget through recovery.
4. Record fresh independent functional and required security receipts with `wave review`. These reviews can run in parallel on the frozen candidate. Verify product criteria, regression boundaries, appropriate reuse, design fidelity and observation dispositions. Candidate changes invalidate receipts; credible HIGH or CRITICAL findings remain blocking. Inspect observations generated by checks and reviews before completion, correcting and refreshing affected evidence as necessary.
5. Record `wave checkpoint <phase> --summary "Verified outcome and decisions" --next "Next action and references"` for the current staged candidate, retaining the delivery scope and branch context under the Git delivery reference. Commit the reviewed tree and run `wave complete <phase> --commit HEAD`. Write `EXPLAIN-POST.simple.md` following the dashboard reference. When publication is authorized, open a draft PR after the first completed phase or update the same PR after subsequent phases; verify its actual remote identity and head. Without authorization, continue locally.
6. Continue dependency-ready work in `loop` without asking the user to test or approve a phase; creating a PR does not pause the loop. Pause at the contract's boundaries in `guided`. After the last phase, execute whole-version verification and obtain an independent delivery review under the execution contract. For enrolled projects, record it with `finish --review FILE`, then run `finish --check`. Correct discovered in-scope defects through an explicit correction phase before claiming completion. Follow the Git delivery reference to publish the final authorized head and mark the PR ready for review. Report the actual outcome, commit, checks, verified PR URL or local-only status, and any real blocker. Merge and deployment remain separate authorized actions.

Perform agent-owned observation triage at every phase under `.riff-codex/references/dashboard.md#end-of-work-observation-triage`, and again for final verification. Inspect current code and evidence, repair confirmed in-scope problems, and record justified decisions through `observations review`. Do not delegate technical validity judgments to the user or mark unverified findings resolved.

Never invoke nested `codex exec`, create a scheduler, publish GitHub issues without an explicit `$riff:issue` request, or use a public `next` command.
